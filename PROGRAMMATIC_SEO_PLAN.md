## 🏗️ Technical Implementation Plan

### 1. URL Structure & Routing

**Recommended URL Patterns:**

```
Location Landing Pages:
/locations/[city]
Example: /locations/toronto

Service Landing Pages:
/services/[service]
Example: /services/curved-cabinetry

Service×Location Pages:
/[city]/[service]
Example: /toronto/kitchen-cabinets

B2B Information Pages:
/builder/[topic]
Example: /builder/pricing
```

**Why `/[city]/[service]`:**
- ✅ Shortest URLs (best UX)
- ✅ City prominence (local SEO boost)
- ✅ Clean, memorable paths
- ✅ Follows location → service hierarchy

### 2. Dynamic Routes to Create

**File**: `src/pages/locations/[city].astro`
- Dynamic route for location landing pages
- Props: city data, services available, local portfolio, contact info

**File**: `src/pages/services/[service].astro`
- Dynamic route for service landing pages (may already exist for some)
- Props: service data, features, process, portfolio, cities served

**File**: `src/pages/[city]/[service].astro`
- Dynamic nested route for service×location pages
- Props: city data + service data, combined content, local portfolio

**File**: `src/pages/builder/[topic].astro`
- Dynamic route for B2B information pages
- Props: builder resources, pricing info, portfolio, contact

### 5. Portfolio Integration

**Portfolio Filtering Strategy:**

```typescript
// Utility function
export function getPortfolioForPage(city?: string, service?: string) {
  let projects = allPortfolioProjects;

  if (city) {
    // Filter by city from MDX frontmatter
    projects = projects.filter(p =>
      p.city.toLowerCase() === city.toLowerCase() ||
      p.location?.includes(city)
    );
  }

  if (service) {
    // Filter by service type from MDX frontmatter
    projects = projects.filter(p =>
      p.services?.includes(service) ||
      p.category === service
    );
  }

  return projects.slice(0, 6); // Show top 6 relevant projects
}
```

**Current Portfolio**: 16 projects in MDX format
- Each has city in frontmatter
- Filter by city for location pages
- Filter by city AND service for service×location pages
- Reuse images across similar services (kitchen is kitchen regardless of city)

### 6. Internal Linking Matrix

**Every Service×Location Page Links To:**
- Parent location page (e.g., `/toronto/kitchen-cabinets` → `/locations/toronto`)
- Parent service page (e.g., `/toronto/kitchen-cabinets` → `/services/kitchen-cabinets`)
- Related services in same city (e.g., Kitchen Cabinets → Kitchen Islands, Pantry)
- Same service in nearby cities (e.g., Toronto Kitchen → Mississauga Kitchen, Oakville Kitchen)
- Homepage and main services page

**Every Location Page Links To:**
- Top 5-10 services available in that city
- Nearby cities (geographic proximity)
- Portfolio projects from that city

**Every Service Page Links To:**
- Top 5-10 cities where service is popular
- Related services (e.g., Kitchen Cabinets → Kitchen Islands, Pantry)
- Portfolio projects featuring that service

**Result**: Strong internal link structure = better SEO
